# PROJECT: Modern Saudi SaaS Accounting & E-Invoicing Platform

We are building a production-grade, multi-tenant SaaS accounting and e-invoicing platform for businesses in Saudi Arabia.

The platform will eventually include:

* Dashboard
* Customers
* Suppliers
* Products & Services
* Quotations
* Sales Invoices
* Credit Notes
* Debit Notes
* Purchases
* Expenses
* Payments
* Chart of Accounts
* Journal Entries
* General Ledger
* Accounts Receivable
* Accounts Payable
* VAT Management
* Financial Reports
* Basic Inventory
* ZATCA E-Invoicing
* Company Management
* User Management
* Audit Logs
* Arabic and English

However, DO NOT build all these modules now.

This first phase is ONLY for establishing the correct production-grade architecture, authentication, multi-tenant structure, application shell, design system, localization framework and initial dashboard shell.

The application must be designed so later modules can be added without rebuilding the foundation.

Create a premium, modern SaaS application comparable in UX quality to leading modern fintech/accounting platforms.

* Interactive
* Trustworthy
* Financially focused

* Giant cards
* Cartoon illustrations
* Excessive icons
* Decorative animations
* AI-looking designs
* Crowded dashboards
* Generic Bootstrap admin appearance

Use whitespace, typography, hierarchy and subtle interactions instead.

# 3. DEPLOYMENT PORTABILITY

The application is currently being developed on Replit.

However, Replit MUST NOT become an architectural dependency.

The application will later be deployed to infrastructure physically hosted in Saudi Arabia.

Therefore:

* Containerize application with Docker.
* Use environment variables.
* Never hardcode Replit-specific URLs.
* Never use Replit proprietary database functionality where it prevents portability.
* PostgreSQL must be independently deployable.
* File storage must use an abstraction layer.
* External integrations must use service adapters.
* Provide Dockerfile.
* Provide docker-compose configuration for local development.

The application should eventually be deployable to Saudi cloud infrastructure without rewriting application code.

# 4. MULTI-TENANT SAAS ARCHITECTURE

This is critical.

Build the platform as multi-tenant from DAY ONE.

Hierarchy:

Platform
→ Organizations
→ Branches
→ Users
→ Roles
→ Business Data

Each company using the SaaS is an Organization.

Every organization-owned business record created later must contain:

organizationId

Never rely only on frontend filtering for tenant isolation.

Tenant isolation must be enforced server-side.

A user may eventually belong to multiple organizations.

Create appropriate models such as:

User

Organization

OrganizationMembership

Role

Permission

Branch

Session

AuditLog

OrganizationSetting

UserPreference

Do not create accounting models yet.
